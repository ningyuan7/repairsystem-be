# 阶段 4：订单 OCR 辅助

已实现持久化 OCR 任务、领取与租约恢复、最多两次自动尝试、迟到结果 CAS 拒绝、人工重新识别、候选字段来源校验和总部采购页的原图对照。识别成功不会修改采购草稿；只有点击应用并保存，才保存经过人工确认的明细。多张截图的明细可分别保留任务与候选项来源。

规则抽取只读取明确标签：订单号、商家/供应商、下单时间、商品/品名、品牌、型号、数量、单价、运费、折扣及合计。没有明确标签或有歧义时保留原文供手填，不编造品牌、型号、数量和价格。置信度与原图坐标来自供应商；无值时返回 null。此规则适配部分常见订单文字，复杂电商版式需要按样本继续扩展。

默认 `REPAIR_OCR_ENABLED=false`，没有凭据时创建任务返回 OCR_NOT_CONFIGURED，采购表单继续可用。实际适配器使用腾讯云 GeneralAccurateOCR / 2018-11-19、固定 HTTPS 域名、TC3 签名、连接及请求超时、有限响应大小、仅瞬态错误重试。配置项为 REPAIR_OCR_SECRET_ID、REPAIR_OCR_SECRET_KEY、REPAIR_OCR_REGION，凭据只从环境读取。每个总部账号默认每分钟 5 次、每天 100 次；同幂等 key 回放不重复创建任务。

实现依据：[腾讯云高精度文字识别接口](https://cloud.tencent.com/document/api/866/34937)、[TC3 签名规范](https://cloud.tencent.cn/document/product/213/30654)。厂商 0–100 置信度归一化为 0–1，保留单位说明。没有新增 SDK 依赖。

## 验证

- 抽取、TC3 签名与供应商合同测试 6 项通过；真实 MySQL OCR 任务测试 6 项通过，覆盖恢复、并发领取、最多两次、迟到拒绝、草稿版本、权限撤销、未绑定图片和缺配置。
- 真实浏览器使用测试专用 FakeOcrClient 完成任务轮询、候选应用、人工修改型号、规格确认及保存来源，桌面与 390px 手机无页面错误和横向溢出。候选出现时采购明细仍为空，证明没有自动写入。
- 前端 TypeScript / Vite 构建通过。日志 `target/repair-phase4-test.log`、`target/repair-phase4-browser-test.log`；截图 `target/repair-ocr-browser/`。

没有使用真实订单图、真实凭据或调用付费 OCR。实际厂商识别准确率与真实网络联调未验证；Fake 只存在测试源码，不能作为实际服务已联调的证据。
