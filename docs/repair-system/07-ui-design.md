# 界面实施依据

## 用户与任务

总部管理员优先处理待审核、待采购和待派单队列，同时维护门店和人员授权；门店管理员快速提交故障并验收；工程师查看本人任务并更新维修过程。第一阶段先交付内部登录、资料完善、成员邀请/授权及门店维护；工单尚未开发时明确显示当前开发范围，不能用虚构统计或工单冒充真实数据。

## 已查阅的参考

- **主参考：[Jira Service Management 队列](https://support.atlassian.com/jira-service-management-cloud/docs/make-queues-for-your-team/)**：借鉴按待办任务筛选队列和列表处理的结构，不复制品牌视觉。
- [Dynamics 365 维修生命周期](https://learn.microsoft.com/en-us/dynamics365/field-service/work-order-status-booking-status)：借鉴安排、现场执行、复核的阶段区分；此处参考已读取的官方流程说明，未声称检查完整产品界面。
- [Ant Design 中文后台规范](https://ant.design/docs/spec/introduce-cn/)：沿用表格、表单、抽屉、操作反馈及状态标签。主要组件体系 Ant Design 5，图标 @ant-design/icons 5，适配现有 React 18。

Mobbin 当前仅可见登录入口，未将其内部界面作为已查阅依据。参考于 2026-10-26 查阅。

## 信息层级与变量

左侧固定功能导航，顶部显示账号和角色，正文依次为页面标题/主操作、范围说明、筛选和表格。总部界面以列表密度服务任务处理，不铺设装饰性统计卡片。手机改为顶部导航及可横向滚动表格，主要表单保持单列。

主色 #3158D5；正文 #1F2937、次要文字 #667085；背景 #F4F6FA、内容白色、边界 #E5E9F0；成功绿色、待处理琥珀色、禁用灰色。字体 system-ui、PingFang SC、Microsoft YaHei；正文 14px/1.6，标题 24/20px，辅助文字 12px；间距 4/8/12/16/24/32px；圆角 8px；仅浮层使用阴影。

所有列表有加载、空白、失败重试；提交期间禁用重复操作；授权变更展示影响；版本冲突保留输入并提示重新加载；邀请链接仅创建时展示，页面不自动发送邮件。资料尚未完整时先完成资料窗口再进入工作台。颜色同时配文字，保留键盘焦点；桌面及 390px 手机宽度截图验收。

## 总部工程师派单一览（2026-10-26）

目标用户为总部管理员，任务是查看工程师当前工作负载并进入原工单处理。沿用上述 Jira 队列主参考、Dynamics 维修阶段和 Ant Design 表格/抽屉规范；没有另设视觉主题。放在工作台待协调事项下方，使用紧凑表格，姓名/电话为一组，显示真实账号状态、四个已派未结阶段和总数。按未结总数降序，保留零任务、缺失电话和停用账号；不推断工程师空闲容量或增加派单限制。

详情用现有风格抽屉显示当前指派工单，支持阶段筛选与独立分页；工单链接进入原详情，去派单进入原待派单队列。沿用蓝色主色、14px 正文、8px 圆角、16/24px 间距、Ant Design 5 与原图标集。补齐初始加载、刷新失败重试、无工程师、无任务、零任务禁用、焦点和 390px 横向表格滚动状态。

## 角色落地与采购派单入口优化

沿用 Jira 队列主参考、Dynamics 维修阶段和 Ant Design 表单，颜色/字体/圆角/间距不变。HQ 工单表新增“下一步”，详情首先呈现审核→订购信息→派单→维修→验收及一项主要操作；审核处理方案必须明确选择，不默认无采购。已确认下单后，在采购页顶部显示可派单提示和工程师选择入口，复用现有派单表单，不改变材料到齐才能开工的规则。无有效工程师时明确提示先邀请或启用人员。

退出清理上次页面；门店/工程师访问总部专属地址时，在挂载受限内容前 replace 到角色自己的工作台，避免先出现 403 或调用无权限接口。后端权限照常校验；允许的工单详情深链接继续保留。空列表、错误重试、保存期间禁用、缺失处理方案验证、无工程师提示和窄屏操作换行均随本次更新验证。
