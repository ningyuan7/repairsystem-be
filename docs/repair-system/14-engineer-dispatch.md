# 总部工程师派单一览

2026-10-26。总部工作台新增只读展示表，位置为“待协调事项”下方。工程师、门店管理员不展示该表，直接请求接口也返回 403。

## 展示与查询口径

每行显示工程师姓名/联系电话、账号启停状态、待接单 ASSIGNED、已接单 ACCEPTED、维修中 IN_PROGRESS、待验收 WAITING_ACCEPTANCE 和未结总数。统计当前 assignee_id 对应的四类未结任务，不包含已完成、已撤销、已驳回或未派单任务；不按日期截断。改派、撤回、退回维修后，下一次刷新按当前记录计算。

按未结总数降序、成员 ID 升序分页，每页默认 10 行。包括零任务、缺少电话和停用工程师，不推断容量、忙闲或自动派单规则。停用显示仅用于总部掌握情况，不改变原“只有有效工程师可被派单”的校验。

查看任务打开抽屉，按工程师与阶段在服务端过滤、分页。按紧急优先、派单时间、工单 ID 排序；展示工单标题/编号/门店、状态、优先级、派单时间，点击工单仍进入原详情。去派单打开原待派单队列，不自动选择工程师或提交派单。

## 接口

- GET `/api/v1/repair/dashboard/engineer-dispatch?page=1&size=10`：Page<EngineerDispatchRow>。
- GET `/api/v1/repair/dashboard/engineer-dispatch/{engineerId}/tickets?page=1&size=10&status=IN_PROGRESS`：Page<DispatchTicket>，status 可省略，仅允许四个未结状态。
- page/size 使用现有分页校验，size 最大 100；未知工程师 404，非总部 403，非法状态或分页 400。
- 汇总先按当前受派人聚合再关联成员，不关联采购明细或事件表，避免任务数量重复计算。无数据库迁移。

原状态流转、权限、派单/改派/撤回、采购、材料到货、验收和费用逻辑未修改。原规则仍为维修中才能改派；待接单/已接单可撤回后重新安排。新增测试按现有规则验证，未为通过测试放宽限制。

沿用现有 Ant Design 与设计参考，详情见 [UI 依据](07-ui-design.md)。有加载、错误重试、真实空白、零任务禁用与键盘可操作控件。390px 下表格仅在容器内横向滚动，并显示滑动提示。轮询沿用工作台的 30 秒可见页面刷新，也支持手动刷新；请求采用顺序标记，过期响应不会覆盖新选择。

浏览器标签图标保持白色工单形状，底色与主界面统一为 #3158D5；资源地址更新缓存版本。
